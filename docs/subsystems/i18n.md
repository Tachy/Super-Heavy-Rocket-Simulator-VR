# Language and report codes (i18n)

The core returns no user text: it reports what happened as a code plus numbers; the game turns that into German or
English from text tables in `config/i18n/`. The language is one saved setting, switchable live.

## Model
- **Report** (`core/include/starsim/report/report.hpp`, namespace `starsim::report`): `Report { Code code; params; causes }`.
  A default report is ok (`ok()`); there is no empty-string-means-ok. `make(code, {params})`, `with_cause(report, cause)`
  nests a report (a code that renders its cause lists `cause` in its params and uses `{cause}` in its text).
  `Refusal` is the exception that carries a report; `config::DataMissing : ConfigError` carries one for player-facing
  missing data.
- **Param kinds** (SI value, no units, no formatting in the core): `angle` (rad), `mass` (kg), `length` (m), `speed`
  (m/s), `time` (s), `count`, `number`, `utc` (Unix seconds, computed in the core), `ref` (a table key, e.g.
  `phase.iss_mission_leg.<id>`, `site.<id>.name`), `data_name` (a verbatim ASCII identifier read from a data file,
  shown as it is). No free text parameters.
- **Codes** (`core/include/starsim/report/codes.def`): `STARSIM_CODE(enumerator, "dotted.id", "param1,param2")`, one per
  line, grouped by area. The enumerator is the id with `.` replaced by `_`. The list is the contract with the tables.
  `internal_error` is the generic code for an unexpected exception turned into a report (the English `what()` goes to
  stderr, never into the shown text); `command.internal_error` is the same for a failed command in the bindings
  (`push_error(what)` + the code).
- **Phase / state ids**: phase and state enums have `id_of(Enum)` with an `// i18n-ns: <namespace>` marker; the table
  key is `phase.<namespace>.<id>` and travels as a `ref` param (snapshots send `"<namespace>.<id>"`, the game calls
  `I18n.phase_text`).
- **Developer rendering**: `report::describe(report)` (code id + params, ASCII) is for logs, test output and the
  campaign text report only, never for the UI.
- **Plan cache**: a cached plan stores its reason report (ids and values); texts never enter the cache hash (the
  `config/i18n/` subtree is excluded from `config_contents_hash`).

## Bindings
`bindings/src/report_dict.{hpp,cpp}`: `report_dict(report)` gives `{code, params, kinds, causes}` (kinds are the
`id_of(Kind)` strings; `ref` / `data_name` params are strings, all others the SI number), `report_array(reports)`.
Command results and snapshots carry reports, not messages. No text is composed in the bindings.

## Text tables
`config/i18n/de.toml` (default) and `en.toml`, read by `TomlLite` (subset: one-line strings, no escapes, no `"` inside
a value, no key that is both a leaf and a prefix). Sections: `[report]` (key `report.<code id>`), `[ui]`, `[wizard]`,
`[event]`, `[hud]`, `[loading]`, `[notice]`, `[phase]`, `[place]`, `[lunar_site]`, `[zone]`, `[vehicle]`, `[mission]`,
`[site]`, `[drone_ship]`, `[gauge]`. Display names of data files live here (`vehicle.<id>.name`, `mission.<id>.name`,
...; the key list is in `config/README.md`). Every key exists in both files with the same placeholder names; English
is natural, short, NASA/ESA usage; no trademarks.

## Game: `I18n` (`game/util/i18n.gd`, static class, no autoload)
- `I18n.text(key, params)`: text of a key in the active language; missing in English -> German; missing in both -> the
  key itself and one warning per key (never empty). `I18n.report_text(dict)` renders a bindings report (`""` for ok,
  nested `causes` through `{cause}`). `I18n.phase_text("<ns>.<id>")`.
- Placeholders `{name}` or `{name:spec}`. Spec = unit + decimals: `deg1`, `t1`, `kg0`, `km2`, `m0`, `mps1`, `kmh0`, `s0`,
  `min1`, `h1`, `pct0`, `n2`, `int`, `clock`, `utc`, `date`. An empty spec takes the kind's default (angle deg1,
  mass t1, length km1, speed mps1, time s0, count int, number n2). German decimal comma, English point; NaN / inf
  show a dash; no negative zero.
- Language: `user://settings.cfg` `[ui] language` (`"de"` default, `"en"`); `I18n.set_language(code)` saves it and emits
  `I18n.events.language_changed(code)`. A temporary control is the language row in the time panel (the start menu will
  bind to the same setting).
- Live switch: displays keep reports and keys as data and resolve them at draw time (`bind_text` re-sets a node's
  property on every change; panels redraw on the signal). The atmosphere status and the loading steps are kept as keys
  too and re-render on a switch.

## Checks
- `python tools/i18n_check.py` (all): `codes` (every code has `report.<id>` in both tables, placeholder names equal the
  listed params), `tables` (same keys in de/en, same placeholders, TomlLite rules), `phases` (every `id_of` phase id has
  a `phase.<ns>.<id>` key), `literals` (no German words / non-ASCII string literals in `core`, `bindings` and non-test
  `game` code, comments excluded; `// i18n-ok:` marks a deliberate exception). `literals <path ...>` scans those
  paths; a directory skips test files like the default scope.
- `python -m pytest tools/test_i18n_check.py -q` tests the checker itself.
- `game/tests/i18n_test.gd` (headless): tables, formatting, reports, the live switch and the saved setting.
- Core: `[report]` cases (`test_report.cpp`), `[plan_cache]` round trip of a report.

## How to add
- **A code**: add a line to `codes.def`, use `report::make(Code::x, {params})`, add `report.<id>` to `de.toml` and
  `en.toml` with the placeholders of the params, run `python tools/i18n_check.py codes tables`.
- **A text**: add the key in both tables (same placeholders), use `I18n.text("section.key", {...})`; keep a report or
  key as data when the display must follow a language switch.
- **A phase / state**: `id_of` with the `// i18n-ns:` marker and `phase.<ns>.<id>` in both tables.
- **A display name**: the key in both tables, not in the data file.

## Standing decisions
- Developer-facing text (config validation errors, internal errors, logs, tests) is English and untranslated.
- Reports are data; text is resolved only when displayed. No grammar engine: plurals and optional clauses are
  separate codes.
- Physics and decisions are unchanged by the conversion; unit tests assert codes and parameters, not text.
